开发基线为本地和 GitHub 一致的 `204b106`。此次变更覆盖任务书列出的五项。Windows 构建使用 0.2.1，以保留之前的 0.2.0 便携包。

| 问题 | 根因及修复 | 验收覆盖 |
| --- | --- | --- |
| P1 流式写放大 | 旧实现每段都重写整个 Turn。现按 25 ms 或 16 KiB 汇集增量，提交到既有 Conversation 事件流，再通知订阅者。检查点和终态压实独立助理快照，历史由快照加该消息的已提交尾部增量重建 | 长文本前后对比、游标顺序、事务回滚重试、旧回复接续、停止和强杀恢复 |
| P2 桌面换模 | 独立 Task 有模型命令，Conversation 缺少控制与回报。新增 `setConversationModel`，通过 JSONL、窄 IPC 和标题栏进入，分开记录已生效与待应用的路由 | 同 Provider 校验、取消、幂等、原 Session 续聊、失败重开和停止竞态 |
| P2 历史重同步 | 重连重建列表、最新快照覆盖旧页。现按 Task ID 与 Host 轮次序号合并，最新权威快照覆盖重叠数据，续页优先补最高缺口 | 65→69 轮重连、超过 50 轮的不相交快照、重复和过期事件 |
| P2 共享契约 | UI 原来经相对路径引用 Host 内部类型。业务 DTO 独立到 `shared/contracts`，Pi Session 文件引用、任务事件和 Context Package 保留在 Host | Host、UI 依赖边界测试，类型检查与桌面打包 |
| P2 脱敏诊断 | 原来丢弃整个 stderr。Host 按固定诊断码发送结构化记录，Electron Main 验证字段、重建本地诊断并按文件大小轮转 | 启动配置与存储失败、Provider 报错、工具失败、伪造字段、敏感字符串、轮转及写盘故障隔离 |

## 长文本实测

在 Windows Node 24.15.0 的本地 SQLite 上，使用同一段 399,360 字节的回复，共 1,024 个输入增量。测试用 SQL trigger 统计写入 `records` 与 `events` 的 UTF-8 逻辑负载。计时覆盖写入和新实现的最终快照，恢复核对单独执行。

| 实现 | 写操作 | 逻辑写入量 | 单次计时 |
| --- | ---: | ---: | ---: |
| 旧逻辑复现，每段重写 Turn | 2,048 | 206,471,609 字节 | 4,094 ms |
| 增量批次与独立快照 | 26 | 809,522 字节 | 58 ms |

逻辑写入量下降 99.6%。两条路径重新打开数据库后，回复和游标与关库前一致。基准不测物理磁盘字节，耗时随机器及负载变化，测试不把耗时作为通过阈值。

## 恢复与运行边界

- 在最迟 25 ms 的正常批次窗口内，尚未提交的文本可能因进程突然退出而丢失。已经通过 Conversation 事件发布的文本已提交，可按 cursor 复原。终态和 Session 检查点先提交待处理输出。
- 0.2.1 可读取 0.2.0 的历史，原回复在首次接续时以已提交游标为界纳入快照。新回复使用新版快照读路径。
- 换模只在下一次自然 Pi 轮次或新消息应用，不额外发送付费请求。已有会话的跨 Provider 请求明确拒绝。若 SDK 正在打开并确认会话，短时换模请求会收到冲突，可在边界结束后重新发起。
- 已加载历史页在当前桌面窗口重连时保留。关闭整个应用后，首次打开按 Host 的最新 50 轮加载，早期历史可以继续分页。
- 日志位于 Electron `userData/logs/diagnostics.jsonl`，保留当前文件及两份轮转，每份最多 256 KiB。日志仅有固定摘要，不含 Provider 原始错误、路径、Prompt 或认证信息。直接运行 Host 时，同次 Agent 激活的模型和工具记录可通过 UUID 关联。桌面日志按 Host 子进程重标记关联 ID。日志为尽力记录，过载和写盘失败时允许丢弃。
