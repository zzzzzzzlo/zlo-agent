# 默认执行额度修复 · 2026-11-18

## 原因与行为

桌面任务在累计第 96 次模型请求后被本地调度器拒绝，最终记录为
`budget_exhausted`。这是程序内置默认值，不是用户配置，也不是模型厂商额度。
此外，Worker 存在默认每次尝试 32 次请求限制，Root 和子 Agent 存在与
fast/quality 模式绑定的固定总运行时间。

默认执行现在没有累计 Token、模型请求次数或任务总时长上限。调度器内部用
Infinity 表示未设请求上限，不将 Infinity/null 写入事件或发送给 Judge；
`model.reserved.taskRequestLimit` 仅在显式配置上限时出现。旧用量账本及恢复
检查点继续保留，不需要清零历史数据。

显式 `modelLimits.requests`、子任务 `budget.requests/timeMs` 仍然有效。
并发资源、单次工具超时、模型自身上下文/输出窗口、权限及未知副作用核对
保持原有职责，不作为累计花费上限。普通任务不需要用户额外开启“无限模式”。

无进展干预沿用 ToolRun：同一失败调用首次失败后允许三次重试，仍未修改
参数或相关工作区时拦截下一次调用。用户停止与检查点恢复保持有效。

## 回归

- 调度器连续 150 次请求，交替结算真实/未知用量，重建调度器后第 151 次
  仍可执行；显式配置上限仍正确拒绝超限请求。
- Host 集成：Root 与真实委派链路中的 Worker 各完成超过 100 次测试模型
  请求，交付通过文件证据检查，不产生隐式总时长或累计请求上限。
- 保留并运行显式 Team 超时、子任务取消、工作区租约释放、用户停止恢复、
  重复失败干预和显式请求额度的原有测试。
- 自动化使用测试执行器，不代表已经发起 200 次付费模型请求。
