基线为 `b1ad4e3`。旧工具适配器只返回 JSON 文本，公共网页浏览器关闭 JavaScript，也不读取 Workspace 页面。本轮通过 Pi 原生图像内容块、独立本地预览和 Coding Workflow 接通反馈。原公共浏览器仍使用原来的静态页面和网络授权。使用方式见 [本地视觉开发](25-visual-development.md)。

- 明确宣告文字能力的模型只收到结构诊断和 `unavailable_on_selected_model`。回归覆盖快速模式、帧数和预览数上限、实际用量核销、重启后未确认预留、最终预览输出上限和最后一轮编辑门槛。视觉事件经过现有遥测白名单。
- WorkBuddy 复核了本地资源精确授权、WebSocket 阻断、图片仅随下一次请求发送，以及重启时未核销预留的处理。对应行为都有回归断言。

## 真实 DeepSeek V4.1 Flash 对照

2026 年 11 月 11 日在 Windows 上以 `deepseek/deepseek-flash` 实际调用同一账户。每个场景的前后版本使用相同任务文本、独立工作区与相同外层限制。Token 为 Provider 返回的未缓存输入、缓存读写与输出之和，缓存 Token 与未缓存 Token 的单价不同。耗时从提交至执行结算，独立复查截图的时间另计。每组为单次样本。

### 相同遮挡初稿，外层预算 120,000 Token

两个初稿都包含覆盖前轮的红色前景块。提示只要求定位明显视觉缺陷并保持构图与运动，没有指出遮挡元素。交付后以 Edge 在 640×360 的同一视口分别复查 0、450、900 ms。

鹈鹕三次预览的反馈阶段分别报告 35,810、43,939 和 6,913 Token，最后一次为复验。两次修改都发生在真实截图进入模型之后。鳄鱼紧预算样本已证明真实截图反馈触发修改，最终三帧由独立渲染确认。更严格的确定性回归对两种动物都要求第二批真实像素经过 Pi 发往供应商替身。

空工作区压力样本促成了最后一次预览的短输出策略，以及高质量模式 192,000 的反馈上限。实测消耗为 128,598 时仍需为最后的上下文和图片预留空间，回归按该记录验证预算。新流程可以提前结束，也可能因为多次复查花费更多 Token。三帧可检查采样时的遮挡、轮胎接触和关节变化，对所有中间帧的运动连续性仍需完整播放或专门的连续验证。现有中台的独立评估继续以原 TaskRun 归档。
