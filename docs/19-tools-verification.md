剩余边界如下。

- Shell/Git 使用当前操作系统账户权限。Windows 子树终止为尽力而为，脱离受控子树的进程不在保证范围。崩溃或停止结果不明时拒绝自动重放，保留需要人工核对的回执。
- 浏览器当前支持受控公共静态页面。JavaScript、表单提交、上传、Cookie 登录、跨来源导航及非 GET 请求受限。Windows 需要系统 Edge，浏览器上下文和 Worktree 均不等同于系统沙箱。
- 免 Key 搜索覆盖 Hacker News 收录内容，通用网页搜索需要配置 Brave Key。Brave 的固定地址和响应适配已自动化测试，线上付费 Provider 未因本轮验证创建新凭证或付费资源。
- Patch 对每个既有文件做一次精确替换，最多 16 文件。跨文件提交可能部分完成，系统保留已发生事实并进入核对。
- Git 仅操作本地。隔离节点只使用文件工具和文件验收，Root 集成后运行受信任项目测试。Worktree 保留供核对，未实现自动清理或销毁用户分支。
- 导出只创建原生系统对话框明确选择的新文件，最多 32 MiB。覆盖现有文件、目录导出、Host 私有目录和额外的外部写权限均不在该授权内。

手工验收可在独立测试目录复现。

1. 选择普通文件写入工作区，让 Agent 搜索文件并提交一次 `apply_patch`，再要求移动、改名和删除指定文件，检查路径与删除确认。
2. 在受信任工作区要求运行一条明确命令，在原生窗口审查完整命令。运行时查询输出、结束时检查退出码，再用长命令验证停止和核对状态。
3. 在有已提交 HEAD 和本地 Git 作者身份的测试仓库创建两个 Worktree，让两个节点分工写入，逐一确认提交与合并。
4. 让 Agent 搜索公开主题、抓取公共 HTTPS 页面，打开浏览器、读取快照并保存工作区 PNG。核对搜索 Provider 的实际覆盖范围。
5. 让 Agent 通过 `export_artifact` 导出生成文件，在系统窗口选择工作区外的新文件，核对内容。拒绝授权和选择已有文件时应保持原文件。
