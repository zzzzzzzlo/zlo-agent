# Zlo Agent · 全新桌面 UI 设计任务书

你负责为 Zlo Agent 从零设计并实现一套 Windows 桌面界面。产品面向用本地 Agent 阅读代码、修改文件和运行开发任务的人。用户应能从接入模型走到交付结果，也能看懂 Agent 正在做什么、哪里出了问题、当前操作会用什么权限。

你可以重新定义导航、页面层级、布局、视觉语言、组件、前端状态组织和用户操作流程。原有界面可以作为功能对照，也可以整体替换。设计从成熟 Agent 产品的实际使用体验出发，例如 [Codex](https://github.com/openai/codex/blob/main/codex-rs/app-server/README.md)、[Claude Code](https://code.claude.com/docs/en/settings) 和 [Mu](https://github.com/qybaihe/mu)。自行决定哪些做法适合 Zlo，并用一份新的界面方案体现这些选择。业务契约和权限边界以本仓库的实际实现为准。

## Agent 已经能做什么

| 能力 | 产品事实 |
| --- | --- |
| Pi Agent Loop | 每轮由 Pi 管理模型请求、回复流、工具调用和后续推理。一次任务可以多次回复、调用工具、观察结果并继续修改。Pi Session 支持保存和继续。 |
| Zlo Harness | 管理任务、工具授权、Workspace、模型路由和预算、指令与 Skills、上下文和 Memory。任务支持追加说明、停止和恢复。 |
| 多 Agent | Root 可委派 Team 和临时 Worker。Task DAG 表达任务依赖，Agent Tree 表达协作关系。授权限制工具和可读写范围。 |
| Coding 与浏览工具 | Agent 可在授权范围内读写文件、搜索、打补丁、执行 Shell、操作 Git、检索公共网页、预览本地页面、截图和读取图片。高风险动作与产物导出沿用系统授权。 |
| 任务与验收 | 执行状态和验收结论各自记录。任务执行完成后可能仍未自动验收。自动验收依赖已配置的文件条件或项目检查。独立中台可另做 AI 评估，桌面暂未提供发起入口或人工验收接口。 |

## UI 会收到什么

| 信息 | 已有数据 |
| --- | --- |
| Host 和会话 | 在线状态、会话摘要、历史分页、实时事件游标、当前工作区与模型。断线后可以重新同步。 |
| 回复 | 用户输入和追加说明、助理 Markdown 原文和增量。历史和实时消息都可以渲染成格式化内容。 |
| 工具调用 | 调用 ID、工具名、状态、AgentRun ID、可选的失败类别及相对助理文本的位置。可以按实际顺序呈现。早期记录可能没有位置。桌面契约没有原始参数、完整 stdout、补丁内容或截图字节。 |
| 任务与协作 | 状态与阻塞原因、任务和尝试 ID、Team/Worker、验收结论、操作回执。详情数据包含任务 DAG 和 Agent Tree。 |
| 资源 | 输入、输出、缓存 Token，模型请求数、工具调用统计、估算费用，以及最近任务的已用、预留和未确认预算。费用可能缺失，供应商剩余额度没有查询接口。 |
| 配置和诊断 | Provider 连接、模型目录、工具目录与授权要求、会话记忆与召回、脱敏诊断。 |

## 开始使用和可修改的选项

使用真实模型前，需要至少有一条已授权、可用的模型路由。用户可以为 DeepSeek、OpenAI、Anthropic 或 Google 配置 API Key，也可以在支持的构建里单独登录 ChatGPT 账号。API Key 通过 Electron Main 的原生确认从剪贴板读取、验证和加密保存。前端接收凭证状态和模型目录。默认模型、默认权限、自动或固定选模、工具开关和搜索 Provider 都是全局可选项。普通任务可以使用默认工作区，文件编辑需要授权写入。

| 会话选项 | 当前支持范围 |
| --- | --- |
| 工作区 | 创建会话时可选择目录。已有会话可以读取当前目录，但没有更换目录的接口。需要在另一个目录工作时，可基于新目录创建会话。 |
| 权限 | 已有会话可在只读、受控写入、受信任执行之间调整。提升须经原生授权，活动任务先停止再提升。收紧会让当前执行收敛。受信任项目代码以本机用户权限运行。 |
| 模型 | 已有会话支持同 Provider 切换，Host 可先返回待生效路由。跨 Provider 需要创建新会话。 |
| 名称与归档 | 会话可改名或归档，归档保留历史。 |
| 验收条件 | 创建时可选文件条件或受信任工作区的项目命令检查。已有会话没有修改条件的接口。 |
| 正在运行的任务 | 可以追加说明、停止和恢复。未知副作用可通过已有核对接口查看后端证据。 |

## 实现与验收

先根据上述事实设计一套新的桌面产品，再在独立分支实现。用新版界面截图或录屏展示设计成果，并在真实 Electron 中用隔离数据和 Faux Provider 验证以下能力。操作入口和流程由你设计。

- 从无可用模型的状态找到接入入口，正确显示授权、连接失败和可用模型。
- 创建会话并选择工作区，在任务前后找到有效权限和模型。能理解当前值、待生效值与变更失败。
- 完成一次真实工具调用，能从聊天找到关键结果和失败原因，并查看该轮工具、Token 与费用数据。回复支持 Markdown 和历史回放。
- 运行中追加说明、停止和恢复。重启应用后能继续查看历史。执行完成、验收结论与异常核对各有明确含义。

接口索引以 [共享契约](../shared/contracts/) 和 [桌面 API 手册](29-frontend-backend-handoff.md) 为准。前端通过 Preload 使用 Host，系统授权、凭证和业务状态由 Main 与 Host 处理。发现尚无接口的交互时，记录缺少的数据或命令以及受影响的流程。交付前运行 [桌面开发说明](../ui/README.md) 中的类型检查、单元测试和 Electron E2E。
